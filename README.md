# おこづかい管理システム

## 1. はじめに

本リポジトリをご覧いただき、ありがとうございます。

前職の株式会社サテライトで、学校連絡アプリ「はなまる連絡帳」のシステム開発を担当した経験をきっかけの一つとして、家庭でのおこづかい管理を支援するWebサービスを開発しました。

機能要件や仕様の検討から、実装、動作確認、問題解決、ConoHa VPSへのデプロイまで一貫して取り組んでいます。開発ではCodexを支援ツールとして活用しながら、自身で設計上の判断と検証を重ねました。公開後も、サービスの改善と運用保守を継続しています。

## 2. コンセプト

子どもの頃、「皿洗いをしたら100円」「お風呂掃除をしたら100円」というように、お手伝いをした分だけ母からおこづかいをもらっていました。その経験から、将来自分の子どもにも、家庭での役割を果たして報酬を得る体験を通じて、働くことの大切さやお金のありがたみを学んでほしいと考えたことが、本サービスの原点です。

一方で、周囲の保護者から話を聞くと、毎月決まった金額を渡す家庭も多くありました。そのため、お手伝い報酬だけでなく、保護者が任意の金額を登録できる「おこづかい入金機能」も用意しています。

対象は小学生から高校生までのお子様とその保護者です。家庭でのおこづかい管理を通じて、子どもがお金について学ぶきっかけを作るとともに、保護者が残高や使用状況を把握しやすくすることを目指しています。

## 4. 機能要件

本システムには、管理を行う「保護者アカウント」と、おこづかいを記録する「お子様アカウント」の2種類があります。

### 保護者向け機能

| 機能 | 概要 |
| --- | --- |
| お子様一覧・管理 | 同じ家族に所属するお子様を一覧表示し、残高や各管理画面を確認できます。 |
| 家族アカウント管理 | 保護者・お子様アカウントの追加、情報変更、削除ができます。 |
| お手伝い報酬設定 | 家族共通のお手伝い名と報酬金額を登録・変更・削除できます。 |
| お手伝い実績管理 | お子様のお手伝い実績を登録し、対応する収入を同時に記録します。登録後の変更・削除にも対応しています。 |
| おこづかい入金 | お子様へ渡した金額を収入として登録し、残高へ反映します。 |
| 履歴・残高確認 | お子様のお手伝い履歴、支出履歴、現在残高を確認できます。 |
| 貯金状況確認 | お子様が設定した目標金額、現在残高、達成率を確認できます。 |
| プロフィール管理 | 表示名とプロフィール画像を変更できます。 |

### お子様向け機能

| 機能 | 概要 |
| --- | --- |
| お子様専用ログイン | 家族コード、ログインID、パスワードを使ってログインできます。家族コードとログインIDはブラウザへの保存も選択できます。 |
| ホーム画面 | 現在残高、直近5件の収支、貯金目標の進み具合をまとめて確認できます。 |
| 支出登録 | 使い道と金額を登録できます。現在残高を超える支出は登録できません。 |
| 支出・お手伝い履歴 | 自分の支出履歴と、報酬を受け取ったお手伝い履歴を確認できます。 |
| 貯金目標 | 欲しい物と目標金額を登録・変更し、達成率を確認できます。 |
| プロフィール管理 | 表示名とプロフィール画像を変更できます。 |

### 共通・認証関連機能

| 機能 | 概要 |
| --- | --- |
| 保護者新規登録時の確認コード | 登録メールアドレスへ4桁の確認コードを送信し、コード確認後に本登録します。有効期限と試行回数の上限を設けています。 |
| 保護者ログイン | Laravel Fortifyを利用したメールアドレス・パスワード認証です。ログイン試行にはレート制限を設定しています。 |
| パスワード再設定 | Fortifyの再設定リンクをメールで送り、新しいパスワードを設定できます。 |
| ロール・家族単位の権限制御 | 保護者用・お子様用画面をMiddlewareで分離し、Policy / Gateで他家族のデータ操作を制限しています。 |

## 6. 実装面の工夫とこだわり

### 子どもにも分かりやすいUIと言葉選び

小学生から高校生までが抵抗なく使えるよう、画面内の情報量を整理し、「支出」などの専門的に感じやすい表現だけに頼らず、「つかったお金」「あといくら？」といった理解しやすい言葉を採用しています。スマートフォンでも操作できるよう、レスポンシブ表示にも対応しています。

### 貯金へのモチベーションを可視化

貯金目標に対する現在残高、残りの金額、達成率を数値とプログレスバーで表示しています。目標までの距離をお子様自身が把握しやすくし、達成時にはメッセージを表示します。保護者側からも同じ進捗を確認できます。

### 収支データを基準にした残高管理

お手伝い報酬とおこづかい入金を収入、お子様が登録した使用記録を支出として `transactions` テーブルへ集約し、収入合計から支出合計を差し引いて残高を算出しています。お手伝い実績と対応する収入は関連付けて保存しています。

### 関連データの整合性

お手伝い実績と収入の登録・変更・削除、支出登録時の残高確認など、複数データに関わる処理にはDBトランザクションを使用しています。更新時には行ロックも利用し、同時操作による不整合を抑えています。

### 履歴を守るデータ設計

ユーザー、お手伝い設定、入金、収支にはSoftDeletesを採用しています。削除済みのお手伝い設定も過去の実績から参照できるよう `withTrashed()` を使用し、設定を削除しても履歴の意味が失われないようにしています。

### 入力値とアクセス権の検証

主要な入力処理はFormRequestへルールと日本語メッセージをまとめています。ロール判定に加え、家族IDを用いたPolicy / Gateで操作対象を検証し、URLを直接変更した場合でも別家族のデータへアクセスできないようにしています。プロフィール画像は形式と容量を検証しています。

### 本番公開後を意識した構成

開発用と本番用のDocker Compose構成を分け、本番ではNginxによるHTTPSへのリダイレクトと、Certbot / Let's Encryptの証明書を利用する構成にしています。主要な認証・権限・保護者／お子様向け機能についてはPestのFeatureテストを配置しています。
